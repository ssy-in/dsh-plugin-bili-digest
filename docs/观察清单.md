## #1 长视频的 @ 门（pending，观察 2–3 天）

- 现象（2026-10-27）：一整天 23 轮，@ 用了 3/5，**全部落在短视频赛道（短 3/3 用完），长视频 0/2 一条没推出去**。
- 初判原因：`pushTasteBar = 0.35`（`lib/core/config.js`）——长视频要过口味分门槛才推，短视频走的是另一套话术/门槛。
- 待确认（看数据，不是看感觉）：
  1. 长视频候选里，`scoreTags(meta.tags).score` 的分布到底落在哪（是不是普遍 0.1–0.3 区间）；
  2. 是门槛太高，还是长视频本身标签就对不上口味（首页推荐的长视频多是游戏/影视剪辑）；
  3. 若确实是门槛问题，候选方案：`0.35 → 0.25`，或对「标签命中任一高权重词（≥0.5）」直接放行。
- 怎么查：
  - `GET <当前 GUI 端口>/bili-digest/api/state` → `push.longLeft / longLimit / shortLeft / today`、`tagBook.taste`；
  - 日报里长视频条数 vs 实际 @ 条数；
  - 需要逐条看分数时，临时写 `.tmp-home/audit-taste.mjs`（读 `cache/feed.json` 队列 + `scoreTags` 打印分布）。

## 每天花 30 秒看一眼的指标

| 指标 | 看哪 | 健康区间 |
| --- | --- | --- |
| 今天读了几条 | `2026MMDD_日记.md` 里 `### ` 的条数 | 10–30 |
| 丢弃比例 | 日报末尾「被丢弃」条数 / 候选数 | 别一路全是 no-subtitle |
| @ 用了多少 | `state.push.today` / `perDay` | 别长期 0（说明门太紧） |
| 请求预算 | `state.budget.used` / 120 | 常态个位数到十几 |
| 心情档分布 | 日记里的「困困鲸此刻」 | 别整天 delighted 或整天 grumpy |
| 消息回复 | `对话.md` | 有问必答、不乱刷 |
